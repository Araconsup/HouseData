# HOUSEDATA — سامانه تحلیل هوشمند و پایش املاک تهران
### Production-Quality Real Estate Ingestion, Anomaly Detection & Market Intelligence Platform

---

## ۱. معرفی و هدف سامانه (Overview)
سامانه **HOUSEDATA** یک وب‌اپلیکیشن جامع، مقیاس‌پذیر و مبتنی بر علم داده است که با هدف گردآوری، پاک‌سازی، نرمال‌سازی، تحلیل آماری و بصری‌سازی آگهی‌های املاک مسکونی و تجاری تهران بر پایه **API رسمی کنار دیوار (Divar Kenar Open API)** توسعه یافته است.

### اهداف بنیادین:
1. **ایجاد پایگاه داده پیوسته رو به گسترش** از قیمت‌های پیشنهادی (Asking Prices) املاک تهران.
2. **محاسبه شاخص‌های آماری مقاوم** (میانه، چارک‌ها، MAD، دامنه بین‌چارکی) در سطوح کل تهران، مناطق ۲۲‌گانه، محلات و بازه‌های متراژ.
3. **موتور تشخیص موارد نامتعارف آماری (Anomaly Detection)** با ۴ مدل مستقل یادگیری ماشین و آمار توصیفی (IQR، زد-اسکور مقاوم، Isolation Forest، و انحراف از میانه محلی).
4. **داشبورد تحلیلی و نقشه تعاملی جغرافیایی** با پشتیبانی کامل از چینش راست‌به‌چپ (RTL)، قلم فارسی وزیرمتن و تبدیل ارقام و واحدهای پولی ایران (تومان).

## ۲. پشته فناوری (Technology Stack)

### بک‌اند (Backend)
- **پایتون**: Python 3.12+ (سازگار با Python 3.13)
- **فریم‌ورک اصلی**: Django & Django REST Framework (DRF)
- **پایگاه داده رابطه‌ای**: PostgreSQL 16 (با پشتیبانی از SQLite برای توسعه سریع محلی)
- **صف کارهای پس‌زمینه (Background Tasks)**: Celery
- **واسط پیام و کش**: Redis
- **کتابخانه‌های علم داده و هوش مصنوعی**:
  - `pandas` و `numpy`: پردازش آرایه‌ها و داده‌های جدولی
  - `scikit-learn`: مدل‌های جنگل ایزولاسیون (`IsolationForest`) و مقیاس‌بندی مقاوم (`RobustScaler`)
  - `scipy`: آمار تحلیلی و توزیع‌ها

### فرانت‌اند (Frontend)
- **طراحی و ساختار**: HTML5 معنایی، CSS مدرن تاریک (Slate Theme) و Responsive
- **رسم نمودارها**: Chart.js 4.4
- **نقشه تعاملی جغرافیایی**: Leaflet.js به‌همراه لایه هیت‌مپ (`Leaflet.heat`)
- **تایپوگرافی**: قلم استاندارد فارسی Vazirmatn (وزیرمتن) با پشتیبانی کامل RTL

### استقرار و زیرساخت (DevOps)
- **کانتینرسازی**: Docker و Docker Compose
- **وب‌سرور و Reverse Proxy**: Nginx
- **WSGI Application Server**: Gunicorn

## ۴. قواعد دقت علمی و شفافیت (Critical Accuracy Rules)
مطابق استانداردهای سخت‌گیرانه داده‌کاوی در املاک:
1. **هیچ‌گاه ادعای «تمام خانه‌های تهران» مطرح نمی‌شود**: جستجوی رسمی دیوار محدود به سقف ۱۰۰ آگهی در هر درخواست است و صفحه‌بندی ندارد. بنابراین سیستم عنوان شفاف **«آگهی‌های مشاهده‌شده در پایگاه داده ما»** را نمایش می‌دهد.
2. **هیچ‌گاه ملکی به عنوان «فرصت حتمی سرمایه‌گذاری» یا «زیر قیمت قطعی» نامیده نمی‌شود**: سیستم عبارات بی‌طرفانه مانند *«از نظر آماری نسبت به املاک مشابه محلی نامتعارف است»* را درج می‌نماید.
3. **حجم نمونه آماری معتبر (N >= 15)**: اگر تعداد املاک همتا کمتر از ۱۵ مورد باشد، سیستم برچسب شفاف **«داده‌های مقایسه‌ای ناکافی»** درج می‌کند تا از ایجاد امتیازهای گمراه‌کننده جلوگیری شود.
4. **تفکیک کامل فروش از رهن و اجاره**: داده‌های خرید و فروش هرگز با داده‌های رهن و اجاره ترکیب نمی‌شوند.

## ۵. راهنمای نصب و راه‌اندازی محلی (Local Development)

### پیش‌نیازها
- Python 3.12 یا 3.13
- ابزار مدیریت پکیج `uv` یا `pip`
- Redis (اختیاری برای اجرای تسک‌های سلری در پس‌زمینه)

### گام ۱: کلون مخزن و راه‌اندازی محیط مجازی
```bash
# ایجاد محیط مجازی با پایتون ۳.۱۲+
python -m venv .venv

# فعال‌سازی در ویندوز (Git Bash):
source .venv/Scripts/activate
# یا در لینوکس / مک:
source .venv/bin/activate

# نصب وابستگی‌ها
pip install -r requirements.txt
```

### گام ۲: تنظیم متغیرهای محیطی
فایل نمونه `.env.example` را به `.env` کپی کنید:
```bash
cp .env.example .env
```
محتوای الزامی `.env`:
```env
DIVAR_API_KEY=
DATABASE_URL=
REDIS_URL=redis://localhost:6379/0
DJANGO_SECRET_KEY=your-secret-key
DEBUG=True
```
> **نکته:** در صورتی که `DIVAR_API_KEY` وارد نشود، سیستم به صورت هوشمند روی **حالت شبیه‌ساز (Mock Mode)** قرار می‌گیرد و بدون هزینه از تولیدکننده داده‌های معتبر تهرانی استفاده می‌کند.

### گام ۳: اجرای مایگریشن‌ها و ایجاد پایگاه داده
```bash
python manage.py migrate
```

### گام ۴: بارگذاری داده‌های واقعی آزمایشی (Seed Mock Data)
برای ایجاد قطعه‌های استاندارد جستجو، ۲۰۰ ملک مسکونی در مناطق ۲۲‌گانه، محاسبات تاریخچه قیمت و تشخیص موارد نامتعارف:
```bash
python manage.py seed_mock_data --count 250
```

### گام ۵: اجرای سرور توسعه
```bash
python manage.py runserver
```
اکنون وارد مرورگر خود شوید:
- **داشبورد اصلی**: `http://localhost:8000/`
- **فهرست املاک**: `http://localhost:8000/listings/`
- **نقشه تعاملی**: `http://localhost:8000/map/`
- **کاوشگر املاک نامتعارف**: `http://localhost:8000/anomalies/`
- **شاخص‌های آماری بازار**: `http://localhost:8000/statistics/`
- **پنل مدیریت جمع‌آوری داده**: `http://localhost:8000/collection/`
- **رابط مدیریت جنگو**: `http://localhost:8000/admin/`

## ۶. اجرای تست‌های خودکار (Automated Tests)
مجموعه تست‌های جامع شامل ۳۴ تست پوشش‌دهنده تمامی اجزا است:
```bash
pytest
```
موارد تحت پوشش تست‌ها:
- کلاینت API رسمی دیوار، هدر `x-api-key`، فیوز ایمنی (Circuit Breaker) و بازآزمایی (Retry Backoff)
- نرمال‌ساز ارقام فارسی/عربی و تبدیل مبالغ تومانی، میلیاردی و میلیون
- موتور انتخاب املاک همتا و ممانعت از ترکیب رهن و فروش
- الگوریتم‌های IQR، زد-اسکور بر پایه MAD، جنگل ایزولاسیون و مدل تجمیعی (Ensemble)
- اعتبارسنجی حجم نمونه (N < 15 -> Insufficient Data)
- تمامی اندپوینت‌های REST API
- پایپ‌لاین تاریخچه قیمت و رهگیری کاهش/افزایش
- تسک‌های پردازش پس‌زمینه Celery

## ۷. استقرار با Docker و Docker Compose (Production Deployment)

پروژه به صورت کامل برای استقرار در محیط پروداکشن با معماری مایکروسرویس آماده است:

```bash
# ساخت ایمیج‌ها و بالا آوردن تمامی کانتینرها
docker compose up --build -d
```

سرویس‌های راه‌اندازی‌شده:
1. `housedata_web`: وب‌سرور جنگو با Gunicorn
2. `housedata_db`: پایگاه داده PostgreSQL 16
3. `housedata_redis`: حافظه موقت Redis 7
4. `housedata_celery_worker`: ورکر سلری برای تسک‌های جمع‌آوری و تحلیل
5. `housedata_celery_beat`: زمان‌بند خودکار تسک‌ها
6. `housedata_nginx`: وب‌سرور معکوس با کش فایل‌های استاتیک روی پورت ۸۰

## ۸. استقرار روی Vercel و قابلیت‌های PWA (Vercel & PWA Support)

### پشتیبانی از وب‌اپلیکیشن پیش‌رونده (PWA)
سامانه به صورت کامل استاندارد PWA را پیاده‌سازی کرده و بر روی تلفن‌های همراه (اندروید و iOS) و دسکتاپ قابل نصب (Installable) به عنوان اپلیکیشن مستقل است:
- **فایل مانیفست**: در مسیر `/manifest.json` با مشخصات تم، آیکون‌های استاندارد ۱۹۲x۱۹۲ و ۵۱۲x۵۱۲، و جهت‌گیری راست‌به‌چپ (`dir: rtl`)
- **سرویس ورکر (Service Worker)**: در مسیر ریشه `/sw.js` با کش هوشمند اَپ‌شل (Stale-While-Revalidate) و استراتژی Network-first برای درخواست‌های API
- **پشتیبانی آفلاین**: بازگشت به صفحه کَش‌شده در زمان قطعی اتصال اینترنت

### استقرار سرورلس روی Vercel
پروژه با فایل‌های [vercel.json](vercel.json) و [build_files.sh](build_files.sh) برای استقرار در بستر Vercel آماده‌سازی شده است:
1. مخزن گیت را به حساب Vercel متصل کنید یا دستور زیر را اجرا نمایید:
   ```bash
   vercel --prod
   ```
2. در پنل Vercel، متغیرهای محیطی زیر را تعریف نمایید:
   - `DJANGO_SECRET_KEY`: کلید امن پروداکشن
   - `DATABASE_URL`: آدرس دیتابیس آنلاین PostgreSQL (مانند Neon, Supabase, یا RDS)
   - `DEBUG`: `False`
   - `DIVAR_API_KEY`: کلید رسمی کنار دیوار (یا خالی برای حالت آزمایشی)

## ۱۰. توسعه‌پذیری و استقلال منبع داده
ساختار ماژولار سامانه به گونه‌ای طراحی شده که جایگزینی یا افزودن منابع داده مجاز ملکی دیگر در آینده بدون نیاز به بازنویسی موتورهای علم داده، انتخاب املاک همتا و محاسبات آماری امکان‌پذیر است.
- لایه اتصال دهنده (`ingestion/client.py`)
- لایه پاک‌سازی (`listings/pipeline.py`)
- لایه علم داده و مدل‌ها (`analytics/detectors.py` و `analytics/comparables.py`)
کاملاً مجزا بوده و داده‌ها را با فرمت استاندارد داخلی مصرف می‌کنند.
